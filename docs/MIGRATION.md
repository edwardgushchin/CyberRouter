# Перенос на другой роутер

Полный профиль доступен в расшифрованном снимке. Точное развёртывание автоматизировано для GL-MT6000 на закреплённой версии OpenWrt. До выбора новой модели нельзя достоверно назначить её Ethernet-порты, Wi-Fi radios и архитектуру бинарников. `deploy` поэтому проверяет плату и прошивку и не имеет флага `--force`.

## Практический порядок переноса

1. Выберите модель с поддерживаемым OpenWrt и ресурсами для Xray, geosite и Go/WebRTC. Исходная система имеет 1 GiB RAM и многогигабайтный overlay; маленькие устройства могут не вместить комплект.
2. Установите **прошивку новой модели**, сохраните её штатные `/etc/config/network`, `/etc/config/wireless`, `/etc/board.json`, список интерфейсов и `ubus call system board`. Нужен доступ по кабелю и рабочий способ восстановления.
3. Расшифруйте исходный снимок по `RECOVERY.md`. Сопоставьте конфигурации приватно. Базовые настройки target network/wireless/board и аппаратные данные остаются от новой модели. Перенесите LAN-адреса, DHCP, VLAN, SSID/ключи и WWAN через UCI с правильными именами портов и radios.
4. По сохранённому списку пакетов установите пакеты **для target/release новой системы**. Драйверы, kernel modules, libc, init и APK-базу Flint 2 не копируйте. Сверьте недоступные пакеты и замените их совместимыми версиями до активации.
5. Перенесите Xray-профили, списки, loader/watchdog/learner/updater и UI. Установите Xray под целевую архитектуру и проверьте все профили через `xray run -test`. Сохраните последовательность правил и теги outbound, ручные/выученные домены и cron.
6. Установите zapret2 под целевую архитектуру и версию firewall; перенесите параметры, Lua и списки из снимка. Сверьте ссылки init и порядок запуска относительно firewall.
7. Перенесите мобильные настройки и UI. Соберите `router-joiner` для новой архитектуры из `components/mobile-backup/router-joiner`; закреплённый модуль `components/relay` уже включён. Сопоставьте radios и физический WAN в controller/UCI/nft. Внешний creator-сервер сохраняется прежним.
8. Проверьте взаимодействие DNS, nftables/TProxy, flow offload, zapret2 и WAN/WWAN. Только затем включите ссылки автозапуска и выполните приёмку клиента по `RECOVERY.md`.
9. После успешного переноса создайте **новый** полный снимок новой модели. Он станет её отдельной точкой восстановления. Текущая версия `prepare` проверяет обязательные компоненты, а `deploy` привязывает полученный комплект к board/release именно его снимка.

## Матрица соответствия для заполнения после выбора устройства

| Параметр | Исходная система | Целевая система |
| --- | --- | --- |
| Board/target | `glinet,gl-mt6000`, `mediatek/filogic` | Из `ubus call system board` |
| Архитектура | aarch64 / ARM64 | Из target и package architecture |
| Ядро/модули | 6.12.74 | Только штатные модули целевой прошивки |
| WAN/LAN/bridge/VLAN | Точное UCI в снимке | По физическим портам новой модели |
| Wi-Fi/STA | Точное UCI в снимке | Имена radios, PHY и доступные диапазоны новой модели |
| Firewall/DNS | nftables, dnsmasq, https-dns-proxy | Совместимые пакеты и include-пути |

Сборка существующего joiner (Go >=1.26.1, зависимости закреплены `go.mod/go.sum`):

```bash
cd components/mobile-backup/router-joiner
go test ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -trimpath -o ../../../private/router-joiner .
```

Измените `GOARCH` только после выбора модели. Восстановление на таком же Flint 2 использует сохранённый рабочий бинарник и не требует Go или пересборки. Произвольная новая модель пока не проходила практическую приёмку.
