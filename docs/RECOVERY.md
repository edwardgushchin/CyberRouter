# Восстановление на чистом Flint 2

Этот маршрут предназначен для **GL.iNet GL-MT6000**, OpenWrt **25.12.2**, revision **r32802-f505120278**, kernel **6.12.74**. Прошивка другой модели и принудительный обход проверки не поддерживаются.

## 1. Получить комплект и ключ

Скопируйте весь Git-репозиторий. Ключ шифрования хранится отдельно: `private/recovery.key` с правами `0600`. При создании проекта дополнительная копия записана в `/home/cybervupsen/.local/share/codex/keys/CyberRouter/recovery.key`. Обе текущие копии находятся на одном компьютере; перенесите одну на внешний носитель или в защищённое хранилище.

```bash
mkdir -m 700 -p private
install -m 600 /путь/к/сохраненному/recovery.key private/recovery.key
python tools/cyberrouter.py open snapshots/2026-09-09 --output private/recovery
python tools/cyberrouter.py prepare private/recovery/capture --output private/restore
python tools/verify-recovery.py private/recovery/capture private/restore
```

`open` проверяет размер и SHA-256 всех частей, собирает ciphertext и проверяет его аутентичность при расшифровании GnuPG. `prepare` сохраняет изменённые файлы и 22 удаления из базовой прошивки. `verify-recovery` сравнивает результат с полным исходным деревом по путям, байтам, ссылкам, правам и владельцам. Расшифрованные файлы остаются в игнорируемом `private/`.

В архиве `access.tar.gz` сохранён клиентский SSH-ключ старого роутера, а SSH host keys и `authorized_keys` входят в файловый снимок. Для восстановления на новом компьютере извлеките `access.tar.gz` в отдельный каталог с правами `0700`; приватному ключу задайте `0600`. Содержимое ключей не выводите в терминал.

## 2. Подготовить замену

Отключите старый роутер от сети перед активацией замены: будут восстановлены прежние LAN-адреса, SSID и SSH-идентичность. Подключите компьютер кабелем к LAN нового устройства.

Проверьте `firmware/SHA256SUMS` из каталога `firmware`:

```bash
(cd firmware && sha256sum -c SHA256SUMS)
```

Установите сохранённый `openwrt-25.12.2-mediatek-filogic-glinet_gl-mt6000-squashfs-sysupgrade.bin` штатным для GL-MT6000 способом. При sysupgrade/LuCI **не сохраняйте старые настройки**. Если загрузчик требует иной тип образа, используйте официальную процедуру именно этой модели; произвольная запись разделов здесь не нужна. Фабричные данные радио и загрузчик не клонируются.

На чистом OpenWrt настройте временный доступ администратора и добавьте свой SSH public key через LuCI/Dropbear. В `~/.ssh/config` создайте алиас `router-replacement` с временным адресом нового роутера, `User root` и своим `IdentityFile`. Инструменты используют `BatchMode=yes`; пароль интерактивно не запрашивается. Интернет на роутере для восстановления не требуется.

## 3. Проверить план и установить

```bash
python tools/cyberrouter.py deploy private/restore --target router-replacement
python tools/cyberrouter.py deploy private/restore --target router-replacement --apply
```

Проверяются board, версия, revision и kernel. Установка отказывается перезаписывать уже настроенный Xray или мобильный резерв. До записи создаётся `before-restore.tar.gz` чистого целевого устройства в закрытом временном каталоге. Устанавливаются сохранённые бинарники пакетов, библиотеки, APK-база, конфигурации, UI, списки и ссылки автозапуска. Пакеты из Интернета не переустанавливаются: используются точные сохранённые файлы.

После копирования проверяются SHA-256 файлов и все Xray-профили. Службы и сеть во время копирования не перезапускаются. Если команда завершилась ошибкой, **не перезагружайте устройство вслепую**: диагностический вывод остаётся в `private/last-error.log`; повторное восстановление выполняется после чистой перепрошивки. Старая рабочая коробка остаётся резервом до приёмки замены.

Перезагрузите только заменяющий роутер явной командой после успешного завершения:

```bash
ssh router-replacement reboot
```

После загрузки он получит сохранённый LAN-адрес; временный SSH-алиас потребуется поправить. Старые профили и сохранённый выбор источника WAN/Wi-Fi тоже восстановятся.

## 4. Приёмка после загрузки

- Вход в LuCI и SSH, совпадение SSID, DHCP-выдача клиенту, работа обоих диапазонов Wi-Fi.
- Доступ обычного клиента к Интернету и DNS; прямой и проксируемый сайты открываются по ожидаемым маршрутам.
- `xray-profile status`, основной и оба резервных профиля; не переключайте профили во время важных сеансов.
- Xray, xray-split, watchdog/learner, dnsmasq, firewall и выбранный режим zapret2 имеют ожидаемое состояние.
- `crontab -l` содержит ежедневное обновление Re:filter в **04:17 MSK**; `/usr/bin/xray-refilter-update` выполняет проверку без изменения уже актуальных данных.
- Мобильная панель LuCI видит выбранный источник; при необходимости обновите истёкшие сессии провайдера. Устройство телефона и внешний creator-сервер должны оставаться доступны.
- В журнале нет циклических падений служб, конфликта DHCP или адресов со старой коробкой.

Снимок сохраняет конфигурацию и постоянные данные. Текущие TCP-сеансы, RAM, DHCP runtime leases, кэш DNS, аппаратная неисправность и срок действия сторонней авторизации не восстанавливаются из Git.

## Аварийные варианты

`sysupgrade.tar.gz` внутри снимка — дополнительная штатная резервная копия конфигурации; одна она не заменяет полный пакет, поскольку не включает все установленные бинарники и наши доработки. `rootfs.tar.gz` — полное постоянное дерево; `upper.tar.gz` — исходный overlay; `rom.tar.gz` — базовая система. Исторические данные находятся в `history.tar.gz` и `local-projects.tar.gz`. Не распаковывайте rootfs поверх рабочей станции или другой модели роутера.
